Normalizacion

Primera Forma Normal - 1FN

El modelo cumple la primera forma normal porque cada campo guarda un solo dato. Por ejemplo, el nombre, el telefono, la fecha o el importe aparecen separados en columnas distintas. Las relaciones de varios a varios no se guardan como listas dentro de una tabla, sino que se crean tablas intermedias.

Segunda Forma Normal - 2FN

El modelo cumple la segunda forma normal porque los atributos dependen de la clave primaria completa. En las tablas con clave compuesta, como ENTRENADOR_ACTIVIDAD, SALA_ACTIVIDAD y ACTIVIDAD_MAQUINARIA, no se añaden datos que dependan solo de una parte de la clave.

Tercera Forma Normal - 3FN

El modelo cumple la tercera forma normal porque se evitan dependencias entre campos que no sean clave. Los datos personales estan en PERSONAS, los datos comunes de empleados estan en TRABAJADORES y los datos concretos de cada rol se separan en tablas como ENTRENADORES o NUTRICIONISTAS. Tambien se separan reservas, pagos, actividades, maquinaria, nutricion y nominas para evitar repeticion de datos.

Campos JSON

Se utilizan campos JSON de forma puntual en SOCIOS y PLANES_NUTRICIONALES. En SOCIOS se usa alergias para guardar informacion sencilla y variable de cada socio. En PLANES_NUTRICIONALES se usa detalle para guardar pautas del plan nutricional. Se usa solo en estos casos porque pueden variar entre usuarios y no siempre tienen la misma estructura.
