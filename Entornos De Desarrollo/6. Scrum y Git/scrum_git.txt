1. INTRODUCCIÓN

El proyecto se ha desarrollado de forma individual. Durante las primeras semanas fui avanzando en las diferentes partes del proyecto y subiendo los cambios al repositorio mediante commits.

Al principio trabajé principalmente sobre la rama main. No tenía todavía organizada la parte de ramas por sprint, por lo que fui guardando los avances directamente en la rama principal.

Más adelante, al revisar los apartados de Entornos de Desarrollo y ver la necesidad de organizar mejor el cierre del proyecto, creé una rama específica para el sprint final de Entornos.

2. USO DE GIT

Git se ha utilizado para guardar el historial del proyecto y controlar los cambios realizados.

Durante las primeras fases se trabajó sobre la rama main. En esta rama se fueron realizando commits con avances como la documentación inicial, diagramas, programación, web y base de datos.

Para la fase final se creó la rama:

sprint-4-cierre-entornos

Esta rama se utiliza para agrupar las tareas finales de Entornos de Desarrollo:

- Scrum
- Git
- JavaDoc
- Pruebas de cobertura
- SonarQube

3. USO DEL TABLERO KANBAN

El proyecto se ha organizado mediante un tablero Kanban en GitHub.

El tablero se divide en tres columnas:

- Todo: tareas pendientes.
- In Progress: tareas en proceso.
- Done: tareas terminadas.

Este tablero ha servido para tener una visión general de lo que estaba hecho, lo que estaba en proceso y lo que quedaba pendiente.

4. ORGANIZACIÓN DEL TRABAJO

Aunque al principio no se trabajó con ramas por sprint, el trabajo se puede agrupar en fases según las tareas realizadas.

FASE 1 - Documentación inicial

En esta fase se trabajaron los primeros documentos del proyecto.

Tareas realizadas:
- Especificación de requisitos.
- Casos de uso.
- Mockup inicial.

FASE 2 - Diagramas

En esta fase se realizaron los diagramas principales del sistema.

Tareas realizadas:
- Diagrama de clases.
- Diagrama de casos de uso.
- Diagramas de secuencia.

FASE 3 - Desarrollo principal

En esta fase se avanzó en la parte de Programación, Lenguaje de Marcas y Bases de Datos.

Tareas realizadas:
- Implementación de clases Java.
- Organización por paquetes.
- Interfaz gráfica básica.
- CRUDs básicos.
- Actividades programadas.
- Web definitiva.
- Generación de JSON desde Java.
- Ampliación de la base de datos.

FASE 4 - Sprint final de Entornos

En esta fase se creó una rama específica para ordenar las tareas finales de Entornos de Desarrollo.

Rama utilizada:
sprint-4-cierre-entornos

Tareas:
- Scrum.
- Git.
- JavaDoc.
- Pruebas de cobertura.
- SonarQube.

5. CONCLUSIÓN

La organización del proyecto ha ido mejorando durante el desarrollo. Al principio se trabajó de forma más sencilla sobre main, haciendo commits de los avances. 
En la fase final se creó una rama de sprint para organizar mejor las tareas pendientes de Entornos.
